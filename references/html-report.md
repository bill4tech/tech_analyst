# HTML 报告规范

单文件、内联 CSS。把 `{skill_dir}/assets/report.css` 全文放进 `<style>`。  
命名 `<YYYYMMDD>-<HHmm>-deep-reverse.html`，写工作目录，完成后 `open` 并告知路径。

与 `apk-reverse-analysis` 共用同一套颜色/标签，便于并排。

## Header 必标

- 包名 / 版本 / 类数 / 加固 / 框架
- **证据级别**（四选一，勿夸大）：
  - 仅静态
  - 静态 + 运行时文件（root 拉数据）
  - 静态 + 流量
  - 含签名重放（需注明已授权）
- **动态状态**：完成 / 部分 / **未执行（原因）**

## 章节

```
一、基本信息
二、技术方案
三、第三方服务（含关键 ID，来源必须可追溯）
四、安全体系（字符串加密、请求加密、环境检测；没有就写未发现）
五、动态分析     ← 卖点提前；未做也保留本章，写原因
   5.1 密钥表（名称→值→来源→分级：硬编码/服务端下发/猜测）
   5.2 游客 vs 登录（做了才有表）
   5.3 运行时证据（logcat / 连接 / 抓包）
六、业务特征
七、权限与导出组件
八、安全评估（不确定用「疑似」）
九、逆向复盘（步骤、跳过项、耗时）
Footer: 对象/时间/工具/"仅用于技术研究与学习目的"
```

## 内容纪律

- 中文；技术名保留原文
- 每个结论带证据（类名、文件、日志）。数字用 `.mono`
- **禁止**写入 `references/cases/` 中其他 App 的密钥/token/域名
- 未跑 ⑥ 不得出现 MMKV JSON、IPC 连接表、登录后 appID
- 动态未完成时用 `.warn-box` 说明缺哪条路径（无 AVD / 未授权 / root 失败 / 加固）
